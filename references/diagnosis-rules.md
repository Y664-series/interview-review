# 诊断、补证据与训练

目标：让用户知道回答哪里成立、哪里有问题，以及下一次怎样答得更好。先完成诊断，再补证据与知识，最后写参考回答。语气自然、正向，仍须做明确判断。

## 判断依据

- 当时表现只依据本次逐字稿及用户提供的当时材料。完整原文放在引用区，保留发言顺序、说话人、时间戳；不擅自选取短句代替整段回答。
- 先串联连续追问：每次回答推进了什么、留下什么、下一问往哪里走。区分自然展开、澄清、挑战和话题迁移；追问本身不等于否定。
- 对面试官意图给有依据的推断，注明转写缺口与其他可能解释，不读心。把用户建议当待评估的分析方向，不直接复制成事实。
- 分清四种缺口：表达（信息组织）、知识（概念或事实）、逻辑（结论缺少前提）、实践证据（个人工作和验证缺失）。允许同时存在，不强制每题都有四类问题。
- 每个关键问题交付：当时回答和遗漏；分类诊断及原文依据；修正方法与证据来源；下一轮可能追问。不能只把原回答改顺。

## 主动核查

遇到概念混用、绝对化或比较性结论、从架构直接推效果、安全或成本、从个人体验推整个人群、从演示推真实成效时，停下来核查。

列清：原主张 → 成立条件 → 当前证据 → 反例或替代解释 → 修正后的判断。需要实测的产品结论不靠网络材料代证。

技术问题优先查官方文档和原始研究。解释来源具体支持什么、未证明什么；区分论文中的评价指标与用户产品的目标。不给研究数字任意换分母或跨任务外推。

## 外部资料的三种用途

1. 同类岗位面经：只用于补追问和训练情境。记录岗位、轮次、作者、发布时间及面试时间；缺失的年份或日期明确写未知。优先原帖，聚合转载降级，来源不明不作主要依据。少量自述不能证明高频，也不能用于断言本场面试官意图。
2. 官方文档、研究、产品资料：核查定义、能力和评测。链接紧邻得到支持的结论，标版本与查阅时间；当前文档不能自动证明过去产品状态。
3. 其他回答或案例：只比较论证结构和验证方式，解释可借鉴之处及不同条件。不得把他人的行动、实验或结果填入候选人的经历。

把“当时已有证据”“事后知识补充”“建议验证方案”分开。外部搜索无法补出本人分工、现场反馈或未发生的实验。

## 修正与追问

参考回答保留“考查点—回答思路（bullet point）—参考回答”的结构，之后增加后续追问。

参考回答要覆盖最关键的论证缺口：需求是谁的、当前替代方案是什么、选择依据是什么、怎样验证、什么结果会改变决定。按题目选适用内容，避免逐题机械套全部字段。

对方案题至少尝试一轮反例或更简单替代方案。需要多方参与时讲清动机、信息来源、授权和确认点；需要有效性主张时讲清基线、评价者、指标与失败条件。未知数据留空，不编造改善比例。

## 评价与行动

默认撤掉无依据的数字评分。用“已展示、展示不足、需要纠正、暂时无法判断”评价，每项关联本场证据。如果用户明确要求分数，先说明维度、锚点和证据覆盖，再评分。

最终行动收敛为最影响下次面试的两三项，注明优先级、要产出的材料和验收方式。逐题保留修正建议；总行动避免重复堆成漫长任务清单。

## 交付检查

- 原文完整保留，分析与原文分开。
- 每个关键判断能回到原文或外部出处；推断有边界。
- 概念问题得到纠正，实践缺口明确交给用户补事实。
- 参考回答经得起列出的后续追问，不只改善措辞。
- 新知识与建议试验没有伪装成候选人的经历。
- 飞书编辑保留现有原文引用与用户已确认结构，按范围更新并回读。
