# 飞书排版与更新

## 页面视觉

标题把公司、团队、轮次放在前面，日期放末尾。例如 `腾讯 WXG · 小微团队｜一面复盘｜2026-10-27`。这是格式示例，不是其他面试的默认信息。

标题下用蓝色加粗的一行展示公司、团队和轮次。最重要的复盘结论放浅蓝提示框；日期、时长及 JD 状态用灰色辅助文字。保留原始妙记和文字记录入口，阅读说明集中写一次。

四大板块用 h1，每题和连续追问分析用 h2；每题的“原文回看”“回答回顾”“建议表达”用 h3。诊断、改进建议、准备材料、继续追问用加粗短标签。保留用户已有标题命名。诊断、回答思路和行动项用 bullet point。

提问清单和评价表采用浅灰表头、加粗列名、顶部对齐，宽列留给原问题或分析，时间和编号列收窄。参考回答放浅蓝提示框，包含“3. 参考回答”标签与完整示范内容；考查点和回答思路放框外。避免整页铺色、过多图标和装饰性分栏。

原文使用原生引用块，每位说话人按原发言分段，保留完整内容和时间戳。长引用不删减、不改为节选。引用与分析、参考回答在视觉上区分。

## 来源定位

原始逐字稿文档按发言分块，保留说话人及时间戳，避免整篇塞入单个代码块。创建后回读真实 block ID，按时间和文本匹配每题开始位置；不能只匹配重复出现的“原文回看”。

在各题“原文回看”旁放“查看原始记录 HH:MM:SS”的链接，采用已取得的源文档 URL 和真实段落锚点；核实匹配的发言属于该题。只有实际验证定位成功才声称能够跳到该段。定位链接不意味着自动同步，用户要求同步块时另行核查当前支持能力。

## 安全更新与核验

- 先 fetch 最新全文和块 ID，使用目标范围替换。保留引用块本身的 ID，尤其是附有用户评论的原文。不要为排版覆盖整份文档。
- 先读取当前 lark-cli 的 lark-doc 和对应 XML/更新参考，使用其支持的标签和样式。不要凭记忆猜测接口；命令或结构不受支持时查帮助后调整。
- 区间匹配限定在当前题标题与下题标题之间，同时处理 p/h3 等已有不同结构。列表外层可能无 ID，范围端点需要从真实子块取得。
- 排版改动前后比较全文文本、完整引用及所有链接，除用户明确要求改写的部分外应保持一致。内容改动时单独核对原文和引用。
- 更新后回读标题、表格、提示框、各题完整引用和来源链接。有浏览器条件时查看开篇与代表性题目，确认表格宽度和回答框可读。
- 保存实际文档 URL 和原文映射，不将某场面试的私有 URL、逐字稿或个人信息写进通用 Skill 包。
